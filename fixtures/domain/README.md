# Pure audio policy fixtures

These are synthetic, hand-reviewed inputs and expected values traced from
`src/indeling.ts`, `src/mixer.ts`, `src/bussen.ts`, `src/handelingen.ts`,
`src/geschiedenis.ts`, `src/meters.ts` and the fader law in `src/Mixer.tsx` at
`fd514a77822ae5a4b3b186dfd541e11fcb882ed0`. No hardware was sampled, no recording
was made, and no JavaScript oracle is needed to run the Rust tests.

- `audio-policy.json` contains duplicate Firefox streams, a mono stream with an
  explicit target, a four-channel AUX output, a hardware source, the actual
  `pecanmixer-opname` node name, a recorder app, virtual hardware, an unknown
  audio class, a hidden monitor and a disabled MIDI node.
- `audio-policy-expected.json` is an authored expectation for strip keys/order,
  channel indices, target eligibility, patchbay groups/visible links, and the
  Back-to-auto inventory. It is not generated by executing the Rust projection.
- `bus-config.json` covers stereo/mono layout, split/join eligibility, fader/mute
  state and arming. This is a test representation, not a WebKit storage importer
  or a persisted native settings schema.

Hand-review details that can be easy to miss:

- Hardware ordering compares subtitles before node IDs and channel indices.
  An unnumbered virtual node has subtitle `playback`, so it precedes the AUX
  pairs whose subtitle is `Studio` in this fixture.
- The first AUX pair is targetable; later pairs require explicit port links.
- Default stream routes are auto regardless of which client created the links.
  Explicit targets make routes manual; Rec bus routes are excluded from cleanup.
- Mono fans in/out; matching channel names take precedence over driver order.
  The existing JavaScript also matches two absent channel names, selecting the
  first destination. The Rust tests preserve that behavior explicitly.
- Bus removal first creates links for shifted later buses, then removes old
  links, then resizes the bus. State follows the surviving logical buses.

The fixture expectations cover ordinary ASCII label ordering. Browser
`localeCompare` parity for international text is not established. The legacy
application remains the production oracle; these fixtures do not establish full
Stage 2 or application parity.
